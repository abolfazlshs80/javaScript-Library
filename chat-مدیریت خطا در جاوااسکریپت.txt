# فصل اول: مقدمه‌ای بر Error Handling

در این فصل موارد زیر را توضیح بده:

## 1.1 خطا چیست؟

توضیح بده:

* Error چیست؟
* چرا خطا در برنامه رخ می‌دهد؟
* چرا مدیریت خطا اهمیت دارد؟
* تفاوت خطای برنامه‌نویسی و خطای قابل پیش‌بینی چیست؟

مثال ساده:

```js
const result = 10 / 0;

console.log(result);
```

توضیح بده که هر نتیجه غیرمنتظره‌ای الزاماً یک Exception نیست.

## 1.2 Error Handling چیست؟

توضیح بده:

* Error Handling یعنی چه؟
* مدیریت خطا چه تفاوتی با جلوگیری از خطا دارد؟
* چرا برنامه نباید با اولین خطا بدون کنترل متوقف شود؟
* آیا باید تمام خطاها را پنهان کنیم؟ چرا؟

## 1.3 چرخه رخ دادن خطا

مراحل زیر را توضیح بده:

1. رخ دادن خطا
2. ایجاد یا پرتاب خطا
3. انتقال خطا در Call Stack
4. پیدا شدن Handler
5. مدیریت یا دوباره پرتاب کردن خطا

## 1.4 مثال واقعی

مثال‌هایی مانند:

* وارد کردن عدد نامعتبر
* پیدا نکردن فایل
* پاسخ ناموفق API
* دسترسی به متغیر تعریف‌نشده
* خطا در تبدیل JSON

در پایان، خلاصه و تمرین ارائه کن.

# فصل دوم: انواع خطا در JavaScript

در این فصل تفاوت انواع خطا را با مثال توضیح بده.

## 2.1 Syntax Error

توضیح بده:

* Syntax Error چیست؟
* چه زمانی رخ می‌دهد؟
* آیا معمولاً قبل از اجرای برنامه تشخیص داده می‌شود؟

مثال:

```js
if (true {
  console.log("Hello");
}
```

## 2.2 Runtime Error

توضیح بده:

* Runtime Error چیست؟
* چه زمانی رخ می‌دهد؟
* چرا ممکن است برنامه تا زمان اجرای یک مسیر خاص بدون مشکل باشد؟

مثال:

```js
const user = null;

console.log(user.name);
```

## 2.3 Logical Error

توضیح بده:

* Logical Error چیست؟
* چرا ممکن است برنامه اجرا شود اما خروجی اشتباه باشد؟
* تفاوت Logical Error با Exception چیست؟

مثال:

```js
function sum(a, b) {
  return a - b;
}

console.log(sum(10, 5));
```

## 2.4 Compile-Time، Parse-Time و Runtime

در حد مناسب برای JavaScript توضیح بده:

* Parse شدن کد
* اجرای کد
* خطاهای زمان تجزیه
* خطاهای زمان اجرا

از ایجاد ادعاهای نادرست درباره کامپایل‌شدن JavaScript خودداری کن.

## 2.5 خطاهای قابل پیش‌بینی و غیرقابل پیش‌بینی

توضیح بده:

* خطای ورودی کاربر
* خطای شبکه
* خطای برنامه‌نویسی
* خطای زیرساخت
* خطای ناشی از داده نامعتبر

در پایان جدول مقایسه‌ای و تمرین ارائه کن.

# فصل سوم: شیء Error در JavaScript

## 3.1 Error چیست؟

توضیح بده که `Error` یک شیء داخلی برای نمایش خطا است.

مثال:

```js
const error = new Error("Something went wrong");

console.log(error);
```

## 3.2 ویژگی‌های مهم Error

هرکدام را ساده و دقیق توضیح بده:

* `name`
* `message`
* `stack`
* `cause`

مثال:

```js
const error = new Error("File not found");

console.log(error.name);
console.log(error.message);
console.log(error.stack);
```

## 3.3 تفاوت Error و String

مثال:

```js
throw "Something went wrong";
```

و:

```js
throw new Error("Something went wrong");
```

توضیح بده چرا استفاده از `Error` معمولاً بهتر است.

## 3.4 Error به‌عنوان Object

توضیح بده:

* Error یک Object است.
* می‌توان ویژگی‌های سفارشی به آن اضافه کرد.
* Error دارای Prototype و زنجیره وراثت است.

مثال:

```js
const error = new Error("Database error");

error.code = "DB_CONNECTION_FAILED";
error.statusCode = 500;

console.log(error.code);
console.log(error.statusCode);
```

# فصل چهارم: دستور throw

## 4.1 throw چیست؟

توضیح بده:

* `throw` برای پرتاب‌کردن خطا یا Exception استفاده می‌شود.
* بعد از اجرای `throw`، ادامه همان مسیر اجرا نمی‌شود.
* خطا به دنبال نزدیک‌ترین `catch` می‌گردد.

مثال:

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error("Division by zero is not allowed");
  }

  return a / b;
}
```

## 4.2 پرتاب Error

```js
throw new Error("Something went wrong");
```

## 4.3 پرتاب انواع دیگر

مثال‌های زیر را نشان بده:

```js
throw "Invalid value";
throw 404;
throw { message: "Not found" };
```

سپس توضیح بده چرا در پروژه‌های واقعی بهتر است Error object پرتاب شود.

## 4.4 تفاوت throw و return

مثال:

```js
function validateAge(age) {
  if (age < 18) {
    throw new Error("Age must be at least 18");
  }

  return true;
}
```

توضیح بده:

* `return` نتیجه عادی برمی‌گرداند.
* `throw` مسیر عادی اجرا را متوقف می‌کند.
* خطای پرتاب‌شده باید در محل مناسب مدیریت شود.

## 4.5 خطا در Call Stack

مثالی چندلایه بنویس:

```js
function levelOne() {
  levelTwo();
}

function levelTwo() {
  levelThree();
}

function levelThree() {
  throw new Error("Failure in level three");
}
```

توضیح بده خطا چگونه در Call Stack حرکت می‌کند.

# فصل پنجم: try...catch

## 5.1 ساختار try...catch

ساختار پایه را توضیح بده:

```js
try {
  // Code that may throw an error
} catch (error) {
  // Handle the error
}
```

## 5.2 مثال ساده

```js
try {
  const result = JSON.parse("invalid json");
  console.log(result);
} catch (error) {
  console.error("An error occurred:", error.message);
}
```

## 5.3 نحوه اجرای try و catch

توضیح بده:

* اگر خطایی رخ ندهد، `catch` اجرا نمی‌شود.
* اگر خطایی رخ دهد، اجرای `try` متوقف می‌شود.
* کنترل به `catch` منتقل می‌شود.
* دستورات بعد از محل خطا در `try` اجرا نمی‌شوند.

## 5.4 متغیر error در catch

توضیح بده:

```js
try {
  throw new Error("Test error");
} catch (error) {
  console.log(error.name);
  console.log(error.message);
}
```

## 5.5 Optional Catch Binding

توضیح بده که در صورت عدم نیاز به خود خطا می‌توان نام آن را حذف کرد:

```js
try {
  riskyOperation();
} catch {
  console.log("Operation failed");
}
```

## 5.6 محدوده متغیر catch

توضیح بده متغیر `error` فقط داخل بلوک `catch` در دسترس است.

## 5.7 مدیریت خطا در توابع

مثال:

```js
function getUserName(user) {
  try {
    return user.name;
  } catch (error) {
    return "Unknown user";
  }
}
```

سپس درباره مزایا و معایب این روش توضیح بده.

# فصل ششم: finally

## 6.1 finally چیست؟

توضیح بده:

* `finally` تقریباً همیشه اجرا می‌شود.
* چه خطا رخ دهد و چه رخ ندهد، `finally` اجرا می‌شود.
* معمولاً برای Cleanup استفاده می‌شود.

مثال:

```js
try {
  console.log("Opening resource");
} catch (error) {
  console.error(error);
} finally {
  console.log("Closing resource");
}
```

## 6.2 کاربردهای finally

مثال‌هایی مانند:

* بستن فایل
* آزاد کردن Connection
* مخفی‌کردن Loading
* فعال‌کردن دوباره دکمه
* پاک‌کردن وضعیت موقت
* آزادکردن منابع

## 6.3 رفتار finally هنگام return

مثال:

```js
function test() {
  try {
    return "try";
  } finally {
    console.log("finally");
  }
}

console.log(test());
```

## 6.4 خطر return در finally

مثال:

```js
function test() {
  try {
    throw new Error("Something went wrong");
  } finally {
    return "Success";
  }
}
```

توضیح بده چرا `return` در `finally` می‌تواند خطا را پنهان کند و چرا معمولاً نباید در `finally` از `return` استفاده کرد.

# فصل هفتم: انواع داخلی خطا

هر نوع را با تعریف، مثال و کاربرد توضیح بده.

## 7.1 Error

```js
throw new Error("General error");
```

## 7.2 TypeError

وقتی نوع یک مقدار برای عملیات موردنظر مناسب نیست.

```js
const user = null;

console.log(user.name);
```

## 7.3 ReferenceError

وقتی به متغیری که وجود ندارد دسترسی پیدا می‌کنیم.

```js
console.log(username);
```

## 7.4 SyntaxError

```js
JSON.parse("{ invalid }");
```

## 7.5 RangeError

وقتی مقدار خارج از محدوده مجاز باشد.

```js
const numbers = [];
numbers.length = -1;
```

یا:

```js
const number = 10;
number.toFixed(200);
```

## 7.6 URIError

مثال:

```js
decodeURIComponent("%");
```

## 7.7 EvalError

توضیح بده که این نوع در JavaScript مدرن کاربرد بسیار محدودی دارد و نباید استفاده از `eval` را توصیه کنی.

## 7.8 AggregateError

توضیح بده:

* برای نمایش چند خطا به‌صورت هم‌زمان استفاده می‌شود.
* در متدهایی مانند `Promise.any()` ممکن است مشاهده شود.

مثال:

```js
const error = new AggregateError(
  [
    new Error("First failure"),
    new Error("Second failure")
  ],
  "All operations failed"
);

console.log(error.message);
console.log(error.errors);
```

## 7.9 DOMException

توضیح بده:

* در برخی Web APIها استفاده می‌شود.
* با Error معمولی تفاوت دارد.
* مثال‌هایی از خطاهای مرورگر ارائه کن.

## 7.10 جدول مقایسه خطاها

جدولی شامل:

* نام خطا
* مفهوم
* مثال
* کاربرد یا علت رایج

# فصل هشتم: تشخیص نوع خطا

## 8.1 استفاده از instanceof

مثال:

```js
try {
  JSON.parse("invalid");
} catch (error) {
  if (error instanceof SyntaxError) {
    console.log("Invalid JSON syntax");
  }
}
```

## 8.2 بررسی name

```js
if (error.name === "TypeError") {
  console.log("A type error occurred");
}
```

## 8.3 تفاوت instanceof و name

توضیح بده:

* `instanceof` زنجیره Prototype را بررسی می‌کند.
* `name` یک property متنی است.
* چه زمانی هرکدام مناسب‌تر است؟
* چرا نباید فقط بر اساس متن پیام خطا تصمیم‌گیری کرد؟

## 8.4 چند نوع خطا در یک catch

مثال:

```js
try {
  riskyOperation();
} catch (error) {
  if (error instanceof TypeError) {
    console.log("Type problem");
  } else if (error instanceof RangeError) {
    console.log("Range problem");
  } else {
    throw error;
  }
}
```

توضیح بده چرا خطاهای ناشناخته بهتر است دوباره پرتاب شوند.

# فصل نهم: Error Propagation و انتقال خطا

## 9.1 Error Propagation چیست؟

توضیح بده خطا چگونه از یک تابع به تابع فراخواننده منتقل می‌شود.

## 9.2 مثال چندلایه

```js
function first() {
  second();
}

function second() {
  third();
}

function third() {
  throw new Error("Something failed");
}

try {
  first();
} catch (error) {
  console.error(error.message);
}
```

## 9.3 نبودن catch

توضیح بده اگر هیچ `catch` مناسبی وجود نداشته باشد، چه اتفاقی می‌افتد.

## 9.4 مدیریت خطا در لایه مناسب

توضیح بده:

* همه توابع نباید خطا را ببلعند.
* لایه پایین معمولاً خطا را ایجاد یا غنی می‌کند.
* لایه بالاتر ممکن است خطا را به کاربر نمایش دهد.
* خطای فنی نباید مستقیماً به کاربر نمایش داده شود.

## 9.5 خطای قابل مدیریت و خطای غیرقابل مدیریت

مثال‌هایی برای هرکدام ارائه کن.

# فصل دهم: Rethrowing Errors

## 10.1 دوباره پرتاب کردن خطا چیست؟

```js
try {
  riskyOperation();
} catch (error) {
  console.error("Logging error");

  throw error;
}
```

## 10.2 چه زمانی باید خطا را دوباره پرتاب کنیم؟

توضیح بده:

* وقتی خطا در این لایه قابل مدیریت نیست.
* وقتی فقط بخشی از اطلاعات خطا ثبت شده است.
* وقتی لایه بالاتر مسئول تصمیم‌گیری است.
* وقتی خطا ناشناخته است.

## 10.3 غنی‌کردن خطا با cause

توضیح بده:

* `cause` چیست؟
* چه زمانی مفید است؟
* چرا بهتر از حذف خطای اصلی است؟

# فصل یازدهم: خطاهای Promise

## 11.1 Promise چیست؟

فقط به‌اندازه لازم توضیح بده:

* سه وضعیت `pending`، `fulfilled` و `rejected`
* rejected شدن Promise به چه معناست؟

## 11.2 reject کردن Promise

```js
const promise = new Promise((resolve, reject) => {
  reject(new Error("Operation failed"));

```

## 11.3 استفاده از catch

```js
promise
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.error(error.message);
  });
```

## 11.4 خطا در then

```js
Promise.resolve()
  .then(() => {
    throw new Error("Error inside then");
  })
  .catch((error) => {
    console.error(error.message);
  });
```

## 11.5 زنجیره Promise

مثال چندمرحله‌ای بنویس و توضیح بده خطا چگونه به `catch` نهایی منتقل می‌شود.

## 11.6 تفاوت throw و reject در Promise

مثال:

```js
Promise.reject(new Error("Rejected promise"));
```

و:

```js
Promise.resolve().then(() => {
  throw new Error("Thrown inside then");
});
```

## 11.7 catch دوباره Promise برمی‌گرداند

توضیح بده:

* `catch()` یک Promise جدید برمی‌گرداند.
* اگر داخل catch مقدار برگردانیم، زنجیره موفق می‌شود.
* اگر داخل catch خطا پرتاب کنیم، Promise جدید rejected می‌شود.

مثال:

```js
Promise.reject(new Error("Initial error"))
  .catch((error) => {
    console.log(error.message);
    return "Fallback value";
  })
  .then((value) => {
    console.log(value);
  });
```

## 11.8 finally در Promise

```js
fetchData()
  .then((data) => {
    console.log(data);
  })
  .catch((error) => {
    console.error(error);
  })
  .finally(() => {
    console.log("Loading finished");
  });
```

* اگر یکی از Promiseها reject شود چه اتفاقی می‌افتد؟
* چگونه خطا را مدیریت کنیم؟

## 11.10 Promise.allSettled

## 11.11 Promise.any و AggregateError

توضیح بده:

* `Promise.any()` چه زمانی reject می‌شود؟
* مفهوم `AggregateError` در آن چیست؟

## 11.12 Promise.race

توضیح بده خطا یا موفقیت اولین Promise چه اثری دارد.

```

و:

```js
fetchData()

  .catch((error) => console.error(error));

## 12.6 خطا در حلقه‌ها

ارائه کن.

## 12.7 مدیریت خطای هر عملیات به‌صورت جداگانه

const results = await Promise.all(

# فصل سیزدهم: مدیریت خطا در fetch و API

## 13.1 آیا fetch برای HTTP Error خطا پرتاب می‌کند؟

این نکته را حتماً توضیح بده:

* `fetch` معمولاً برای خطاهای شبکه reject می‌شود.
* پاسخ‌هایی مانند `404` و `500` لزوماً باعث reject شدن Promise نمی‌شوند.
* باید `response.ok` یا `response.status` بررسی شود.

## 13.2 مثال اشتباه

```js
const response = await fetch("/api/users");

const data = await response.json();
```

توضیح بده چرا این کد به‌تنهایی کافی نیست.

## 13.3 مثال صحیح

```js
async function getUsers() {
  const response = await fetch("/api/users");

  if (!response.ok) {
    throw new Error(`Request failed with status ${response.status}`);
  }

  return response.json();
}
```

## 13.4 مدیریت خطای شبکه و HTTP

مثال کامل:

```js
async function getUsers() {
  try {
    const response = await fetch("/api/users");

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    console.error("Could not load users:", error);
    throw error;
  }
}
```

## 13.5 خطای JSON

توضیح بده اگر پاسخ JSON معتبر نباشد چه اتفاقی رخ می‌دهد.

## 13.6 AbortController

توضیح بده:

* چرا باید درخواست را لغو کنیم؟
* چگونه Timeout یا Cancel ایجاد کنیم؟
* تفاوت خطای لغو با خطای واقعی چیست؟

مثال:

```js
const controller = new AbortController();

fetch("/api/users", {
  signal: controller.signal
});

controller.abort();
```

## 13.7 ساخت خطای API سفارشی

مثال:

```js
class ApiError extends Error {
  constructor(message, status, options = {}) {
    super(message, options);

    this.name = "ApiError";
    this.status = status;
  }
}
```

# فصل ۱: مقدمه‌ای بر Error Handling

## مقدمه
هر برنامه‌نویسی، از مبتدی تا حرفه‌ای، با خطا مواجه می‌شود. تفاوت یک برنامه‌نویس حرفه‌ای با یک مبتدی در این نیست که کدام‌یک کد بدون خطا می‌نویسد (چنین چیزی وجود ندارد)، بلکه در این است که چگونه خطاها را پیش‌بینی، مدیریت و از تأثیر مخرب آن‌ها جلوگیری می‌کند. در این فصل، مفاهیم بنیادین خطا و مدیریت آن را بررسی می‌کنیم.

## مفهوم اصلی
### ۱.۱ خطا (Error) چیست؟
خطا (Error) یا استثنا (Exception) رویدادی غیرمنتظره است که جریان عادی اجرای برنامه را مختل می‌کند. خطاها به دلایل مختلفی رخ می‌دهند: ورودی نامعتبر کاربر، قطعی شبکه، دسترسی به منابع ناموجود یا اشتباهات منطقی در کد.

**تفاوت خطای برنامه‌نویسی و خطای قابل پیش‌بینی:**
- **خطای برنامه‌نویسی (Programming Error):** ناشی از باگ در کد است (مثل دسترسی به متغیر تعریف‌نشده). این خطاها باید در مرحله توسعه رفع شوند.
- **خطای قابل پیش‌بینی (Predictable Error):** ناشی از شرایط محیطی است (مثل پر بودن فضای دیسک یا قطع اینترنت). این خطاها باید در کد مدیریت شوند.

> **نکته مهم:** هر نتیجه غیرمنتظره‌ای لزوماً یک Exception نیست.
> ```js
> const result = 10 / 0;
> console.log(result); // خروجی: Infinity
> ```
> در جاوااسکریپت، تقسیم بر صفر باعث پرتاب خطا (Exception) نمی‌شود، بلکه مقدار ویژه `Infinity` را برمی‌گرداند. این یک رفتار تعریف‌شده در استاندارد زبان است، نه یک خطای اجرایی.

### ۱.۲ Error Handling (مدیریت خطا) چیست؟
مدیریت خطا به معنای نوشتن کدی است که واکنش مناسبی به وقوع خطا نشان دهد. 
- **تفاوت با جلوگیری از خطا (Prevention):** جلوگیری از خطا یعنی اعتبارسنجی داده‌ها قبل از انجام عملیات (مثل بررسی خالی نبودن یک فرم). مدیریت خطا یعنی واکنش به خطایی که با وجود تمام پیش‌بینی‌ها، رخ داده است.
- **چرا برنامه نباید بدون کنترل متوقف شود؟** توقف ناگهانی (Crash) باعث از دست رفتن داده‌ها و تجربه کاربری بسیار بد می‌شود. مدیریت خطا به برنامه اجازه می‌دهد به‌جای توقف، به حالت امن بازگردد یا پیام مناسبی نمایش دهد.
- **آیا باید تمام خطاها را پنهان کنیم؟** خیر. پنهان‌کردن خطاهای برنامه‌نویسی (مثل باگ‌های منطقی) باعث می‌شود اشکالات در تولید (Production) باقی بمانند. خطاهای محیطی باید مدیریت شوند، اما خطاهای برنامه‌نویسی باید گزارش (Log) و رفع شوند.

### ۱.۳ چرخه رخ دادن خطا
وقتی خطایی رخ می‌دهد، معمولاً این ۵ مرحله را طی می‌کند:
1. **رخ دادن خطا (Occurrence):** یک عملیات ناموفق انجام می‌شود.
2. **ایجاد یا پرتاب خطا (Throwing):** موتور جاوااسکریپت یا کد نویسنده، یک شیء خطا ایجاد و پرتاب (`throw`) می‌کند.
3. **انتقال خطا در Call Stack (Propagation):** اگر خطا در تابع فعلی مدیریت نشود، به تابع فراخواننده (Caller) و سپس به تابع بالاتر منتقل می‌شود.
4. **پیدا شدن Handler (Capturing):** موتور جاوااسکریپت به دنبال نزدیک‌ترین بلوک `catch` می‌گردد.
5. **مدیریت یا دوباره پرتاب کردن (Handling/Rethrowing):** خطا یا در `catch` مدیریت می‌شود، یا اگر مدیریت‌شدنی نباشد، دوباره پرتاب می‌شود تا لایه‌های بالاتر آن را مدیریت کنند.

### ۱.۴ مثال‌های واقعی از خطا
- **وارد کردن عدد نامعتبر:** کاربر در فیلد سن، حروف وارد می‌کند.
- **پیدا نکردن فایل:** تلاش برای خواندن فایلی که وجود ندارد (`ENOENT` در Node.js).
- **پاسخ ناموفق API:** سرور پاسخ `500 Internal Server Error` می‌دهد.
- **دسترسی به متغیر تعریف‌نشده:** تلاش برای خواندن `user.address` وقتی `user` مقدار `null` دارد.
- **خطا در تبدیل JSON:** تلاش برای `JSON.parse` روی یک رشته که فرمت JSON معتبر ندارد.

## اشتباهات رایج
- تصور اینکه `try...catch` همه مشکلات (مثل خطاهای Syntax) را حل می‌کند.
- نادیده گرفتن خطاها و رها کردن بلوک `catch` به‌صورت خالی.

## نکات مهم
- خطا (Error) با نتیجه غیرمنتظره (مثل `NaN` یا `Infinity`) تفاوت دارد.
- هدف مدیریت خطا، جلوگیری از توقف ناگهانی برنامه و ارائه بازخورد مناسب است.
- خطاهای برنامه‌نویسی باید رفع شوند، نه اینکه فقط مدیریت (پنهان) شوند.

## تمرین
1. یک تابع بنویسید که دو عدد را از ورودی بگیرد و حاصل تقسیم آن‌ها را برگرداند. اگر عدد دوم صفر بود، به‌جای برگرداندن `Infinity`، یک پیام خطای متنی مناسب در کنسول چاپ کند (بدون استفاده از `throw`).
2. فکر کنید و بنویسید: چرا `JSON.parse("undefined")` باعث خطا می‌شود، اما `JSON.parse("null")` خطایی ایجاد نمی‌کند؟

## جمع‌بندی
در این فصل یاد گرفتیم که خطا بخشی اجتناب‌ناپذیر از توسعه نرم‌افزار است. درک تفاوت بین خطای برنامه‌نویسی و خطای محیطی، و شناخت چرخه حیات یک خطا، پایه‌ای‌ترین قدم برای نوشتن کدهای مقاوم است. در فصل بعد، انواع مختلف خطا را از نظر فنی بررسی خواهیم کرد.

# فصل ۲: انواع خطا در JavaScript

## مقدمه
همه خطاها یکسان نیستند. برخی از آن‌ها قبل از اجرای برنامه قابل تشخیص‌اند، برخی در حین اجرا رخ می‌دهند و برخی دیگر باعث می‌شوند برنامه بدون هیچ خطای آشکاری، خروجی اشتباه تولید کند. درک این تفاوت‌ها برای عیب‌یابی (Debugging) حیاتی است.

## مفهوم اصلی
### ۲.۱ خطای سینتکس (Syntax Error)
خطای سینتکس زمانی رخ می‌دهد که کد نوشته‌شده با قوانین گرامری زبان جاوااسکریپت مطابقت نداشته باشد.
- **چه زمانی رخ می‌دهد؟** در مرحله تجزیه (Parse-Time)، قبل از اینکه کد اصلاً اجرا شود.
- **تشخیص:** معمولاً توسط ویرایشگر کد (IDE) یا موتور جاوااسکریپت بلافاصله شناسایی می‌شود و اجازه اجرای برنامه را نمی‌دهد.

```js
// مثال اشتباه
if (true {
  console.log("Hello");
}
```
**خروجی:** `SyntaxError: Unexpected token '{'`
**دلیل:** پرانتز باز `(` بسته نشده است. موتور جاوااسکریپت نمی‌تواند این کد را تجزیه کند، بنابراین اجرا اصلاً شروع نمی‌شود.

### ۲.۲ خطای زمان اجرا (Runtime Error)
خطای زمان اجرا زمانی رخ می‌دهد که کد از نظر سینتکس صحیح است، اما در حین اجرا با شرایطی مواجه می‌شود که نمی‌تواند پردازش کند.
- **چه زمانی رخ می‌دهد؟** فقط زمانی که خط اجرای برنامه (Execution Path) به آن خط خاص برسد.
- **چرا ممکن است برنامه تا آن لحظه بدون مشکل باشد؟** اگر کد حاوی خطا درون یک شرط یا تابع باشد که هرگز فراخوانی نشود، برنامه بدون مشکل اجرا می‌شود.

```js
const user = null;
// تا اینجا برنامه سالم است
console.log(user.name); // خطا اینجاست
```
**خروجی:** `TypeError: Cannot read properties of null (reading 'name')`
**دلیل:** متغیر `user` مقدار `null` دارد و `null` یک شیء نیست که ویژگی `name` داشته باشد.

### ۲.۳ خطای منطقی (Logical Error)
خطرناک‌ترین نوع خطا، خطای منطقی است. در این حالت، برنامه بدون هیچ پیام خطایی اجرا می‌شود، اما خروجی آن با آنچه انتظار داریم متفاوت است.
- **تفاوت با Exception:** موتور جاوااسکریپت هیچ خطایی پرتاب نمی‌کند، زیرا کد از نظر فنی "معتبر" است، اما منطق برنامه‌نویس اشتباه است.

```js
function sum(a, b) {
  return a - b; // اشتباه منطقی: باید a + b باشد
}

console.log(sum(10, 5)); // خروجی: 5 (انتظار داشتیم 15 باشد)
```
**دلیل:** عملگر ریاضی اشتباه استفاده شده است. موتور جاوااسکریپت این را یک عملیات ریاضی معتبر می‌داند و خطایی پرتاب نمی‌کند.

### ۲.۴ مفاهیم Parse-Time و Runtime در JavaScript
جاوااسکریپت یک زبان مفسری (Interpreted) و JIT-Compiled است.
1. **Parse-Time (زمان تجزیه):** موتور جاوااسکریپت کد را می‌خواند و به ساختار درختی (AST) تبدیل می‌کند. خطاهای `SyntaxError` در این مرحله رخ می‌دهند.
2. **Runtime (زمان اجرا):** کد تجزیه‌شده اجرا می‌شود. خطاهای `TypeError`، `ReferenceError` و غیره در این مرحله رخ می‌دهند.

### ۲.۵ خطاهای قابل پیش‌بینی و غیرقابل پیش‌بینی
| نوع خطا | منبع خطا | مثال | قابلیت پیش‌بینی |
| :--- | :--- | :--- | :--- |
| **ورودی کاربر** | کاربر نهایی | وارد کردن حروف در فیلد عددی | کاملاً قابل پیش‌بینی (باید اعتبارسنجی شود) |
| **شبکه** | زیرساخت اینترنت | قطع اتصال هنگام `fetch` | قابل پیش‌بینی (باید Retry یا پیام خطا نمایش داده شود) |
| **برنامه‌نویسی** | توسعه‌دهنده | فراخوانی متد روی `undefined` | غیرقابل پیش‌بینی در تولید (باید با تست جلوگیری شود) |
| **زیرساخت** | سرور/دیتابیس | پر شدن فضای دیسک سرور | قابل پیش‌بینی (باید مانیتورینگ و مدیریت شود) |
| **داده نامعتبر** | API خارجی | دریافت ساختار JSON متفاوت از قرارداد | قابل پیش‌بینی (باید با Schema Validation بررسی شود) |

## اشتباهات رایج
- تلاش برای گرفتن خطای `SyntaxError` با `try...catch` (غیرممکن است، زیرا کد اصلاً اجرا نمی‌شود).
- فرض اینکه اگر کد اجرا شد و خطایی نداد، پس منطق آن درست است.

## نکات مهم
- `SyntaxError` مانع اجرای کل اسکریپت می‌شود.
- `Runtime Error` فقط مسیر اجرای فعلی را متوقف می‌کند (اگر مدیریت نشود، کل برنامه را متوقف می‌کند).
- `Logical Error` توسط موتور جاوااسکریپت شناسایی نمی‌شود و نیاز به Unit Testing دارد.

## تمرین
1. سه قطعه کد بنویسید: یکی که `SyntaxError` تولید کند، یکی `Runtime Error` و یکی `Logical Error`.
2. چرا کد زیر باعث خطای زمان اجرا نمی‌شود، هرچند که تابع `brokenFunction` هرگز تعریف نشده است؟
   ```js
   console.log("Start");
   if (false) {
       brokenFunction();
   }
   console.log("End");
   ```

## جمع‌بندی
تشخیص نوع خطا، اولین قدم برای حل آن است. خطاهای سینتکس توسط ابزارهای توسعه شناسایی می‌شوند، خطاهای زمان اجرا باید با `try...catch` مدیریت شوند و خطاهای منطقی نیازمند نوشتن تست و بازبینی کد هستند.
```

# فایل `03-error-object.md`

```markdown
# فصل ۳: شیء Error در JavaScript

## مقدمه
در جاوااسکریپت، خطاها فقط پیام‌های متنی ساده نیستند؛ آن‌ها اشیایی (Objects) با ساختار مشخص‌اند که اطلاعات ارزشمندی درباره چرایی و محل وقوع خطا ارائه می‌دهند. درک ساختار شیء `Error` برای عیب‌یابی حرفه‌ای ضروری است.

## مفهوم اصلی
### ۳.۱ Error چیست؟
`Error` یک کلاس داخلی (Built-in Constructor) در جاوااسکریپت است که برای ایجاد یک شیء خطا استفاده می‌شود. وقتی خطایی رخ می‌دهد، موتور جاوااسکریپت نمونه‌ای از این کلاس (یا زیرکلاس‌های آن) را ایجاد می‌کند.

```js
const error = new Error("Something went wrong");
console.log(error);
```
**خروجی:** `Error: Something went wrong` (همراه با Stack Trace در محیط اجرا)
**دلیل:** ما به‌صورت دستی یک نمونه از کلاس `Error` با پیام مشخص ایجاد کردیم.

### ۳.۲ ویژگی‌های مهم Error
هر شیء `Error` به‌طور پیش‌فرض دارای ویژگی‌های (Properties) زیر است:
- **`name`**: نام نوع خطا (مثلاً `"Error"`, `"TypeError"`, `"ReferenceError"`).
- **`message`**: پیام توصیفی خطا که توسط برنامه‌نویس یا موتور جاوااسکریپت تنظیم می‌شود.
- **`stack`**: (فقط خواندنی) رشته‌ای که مسیر فراخوانی توابع (Call Stack) را از محل ایجاد خطا تا ریشه نشان می‌دهد. این مهم‌ترین ویژگی برای عیب‌یابی است.
- **`cause`**: (اضافه‌شده در ES2022) اجازه می‌دهد یک خطای دیگر را به‌عنوان علت ریشه‌ای (Root Cause) این خطا مشخص کنیم.

```js
const error = new Error("File not found");
console.log(error.name);    // خروجی: "Error"
console.log(error.message); // خروجی: "File not found"
console.log(error.stack);   // خروجی: مسیر کامل فراخوانی توابع
```

### ۳.۳ تفاوت پرتاب Error و String
در جاوااسکریپت شما می‌توانید هر مقداری را `throw` کنید، اما این کار توصیه نمی‌شود.

```js
// مثال اشتباه (پرتاب رشته)
throw "Something went wrong";

// روش صحیح (پرتاب شیء Error)
throw new Error("Something went wrong");
```
**چرا استفاده از `Error` بهتر است؟**
وقتی یک رشته پرتاب می‌کنید، ویژگی `stack` (مسیر فراخوانی) را از دست می‌دهید و تشخیص نوع خطا در بلوک `catch` بسیار دشوار می‌شود. شیء `Error` اطلاعات کامل عیب‌یابی را حفظ می‌کند.

### ۳.۴ Error به‌عنوان Object
از آنجا که `Error` یک شیء است، می‌توانیم ویژگی‌های سفارشی به آن اضافه کنیم تا اطلاعات بیشتری منتقل شود. این کار برای خطاهای سفارشی بسیار مفید است.

```js
const error = new Error("Database connection failed");
error.code = "DB_CONNECTION_FAILED";
error.statusCode = 500;

console.log(error.code);       // خروجی: "DB_CONNECTION_FAILED"
console.log(error.statusCode); // خروجی: 500
```
**دلیل:** جاوااسکریپت اجازه افزودن ویژگی‌های دلخواه به اشیاء را می‌دهد. این کار به لایه‌های بالاتر اجازه می‌دهد تا بر اساس `statusCode` یا `code` تصمیم‌گیری کنند، نه فقط بر اساس متن پیام.

## اشتباهات رایج
- استفاده از `throw "Error message"` به‌جای `throw new Error("Error message")`.
- تلاش برای تغییر ویژگی `stack` (این ویژگی معمولاً فقط خواندنی است و دستکاری آن رفتارهای غیرقابل پیش‌بینی دارد).

## نکات مهم
- همیشه برای پرتاب خطا از `new Error()` یا زیرکلاس‌های آن استفاده کنید.
- ویژگی `stack` فقط در زمانی که خطا `throw` می‌شود یا شیء `Error` ساخته می‌شود، پر می‌شود.
- از ویژگی `cause` برای زنجیره‌کردن خطاها و حفظ زمینه (Context) اصلی خطا استفاده کنید.

## تمرین
1. یک شیء `Error` ایجاد کنید که دارای ویژگی‌های سفارشی `userId` و `action` باشد. سپس در یک بلوک `try...catch` آن را پرتاب کرده و این ویژگی‌ها را در `catch` خوانده و چاپ کنید.
2. تفاوت خروجی `console.log(new Error("test").stack)` در محیط Node.js و Browser را بررسی کنید.

## جمع‌بندی
شیء `Error` قلب تپنده مدیریت خطا در جاوااسکریپت است. این شیء نه‌تنها پیام خطا، بلکه مسیر فراخوانی (Stack Trace) و امکان افزودن داده‌های سفارشی را فراهم می‌کند که برای عیب‌یابی در محیط‌های تولید (Production) حیاتی است.
```

# فایل `04-throw-statement.md`

```markdown
# فصل ۴: دستور throw

## مقدمه
تا اینجا دیدیم که موتور جاوااسکریپت چگونه خطاها را ایجاد می‌کند. اما به‌عنوان توسعه‌دهنده، ما نیز باید بتوانیم به‌صورت عمدی و در شرایط خاص، خطا ایجاد کنیم. این کار با دستور `throw` انجام می‌شود.

## مفهوم اصلی
### ۴.۱ throw چیست؟
دستور `throw` برای پرتاب‌کردن (ایجاد) یک خطا یا Exception استفاده می‌شود. 
- وقتی `throw` اجرا می‌شود، **اجرای عادی کد در آن مسیر بلافاصله متوقف می‌شود**.
- موتور جاوااسکریپت شروع به جستجو در Call Stack می‌کند تا نزدیک‌ترین بلوک `catch` را برای مدیریت این خطا پیدا کند.

### ۴.۲ پرتاب Error (روش استاندارد)
همیشه بهترین روش، پرتاب یک نمونه از کلاس `Error` یا زیرکلاس‌های آن است.

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error("Division by zero is not allowed");
  }
  return a / b;
}

// divide(10, 0); // اگر این خط اجرا شود، برنامه متوقف و خطا پرتاب می‌شود
```
**دلیل:** این کار به فراخواننده تابع اطلاع می‌دهد که ورودی نامعتبر است و اجازه نمی‌دهد عملیات ریاضی نامعتبر (که منجر به `Infinity` می‌شود) به‌صورت خام ادامه یابد.

### ۴.۳ پرتاب انواع دیگر (فقط برای درک رفتار زبان)
جاوااسکریپت به شما اجازه می‌دهد هر مقداری را پرتاب کنید، اما این کار در پروژه‌های واقعی **توصیه نمی‌شود**.

```js
throw "Invalid value";      // پرتاب رشته
throw 404;                  // پرتاب عدد
throw { message: "Not found" }; // پرتاب شیء معمولی
```
**چرا در پروژه‌های واقعی بهتر است Error object پرتاب شود؟**
زیرا اگر یک رشته یا عدد پرتاب کنید، در بلوک `catch` نمی‌توانید از ویژگی‌های استاندارد مثل `error.stack` یا `error.name` استفاده کنید و ابزارهای مانیتورینگ خطا (مثل Sentry) نمی‌توانند آن را به‌درستی ردیابی کنند.

### ۴.۴ تفاوت throw و return
- `return`: اجرای تابع را با موفقیت به پایان می‌رساند و یک مقدار را به فراخواننده برمی‌گرداند.
- `throw`: اجرای تابع را به‌صورت **ناموفق** و ناگهانی متوقف می‌کند و کنترل را به مدیریت‌کننده خطا (Error Handler) می‌سپارد.

```js
function validateAge(age) {
  if (age < 18) {
    throw new Error("Age must be at least 18"); // توقف ناگهانی
  }
  return true; // بازگشت موفقیت‌آمیز
}
```

### ۴.۵ خطا در Call Stack (پشته فراخوانی)
وقتی خطایی پرتاب می‌شود، اگر در تابع فعلی `catch` نباشد، به تابعی که آن را فراخوانده منتقل می‌شود.

```js
function levelOne() {
  levelTwo();
}

function levelTwo() {
  levelThree();
}

function levelThree() {
  throw new Error("Failure in level three");
}

try {
  levelOne();
} catch (error) {
  console.error("Caught:", error.message);
}
```
**خروجی:** `Caught: Failure in level three`
**دلیل:** خطا در `levelThree` پرتاب می‌شود. چون آنجا `catch` نیست، به `levelTwo`، سپس به `levelOne` و در نهایت به بلوک `try...catch` اصلی منتقل می‌شود. اگر `try...catch` در هیچ‌کجا نبود، برنامه کرش می‌کرد.

## اشتباهات رایج
- استفاده از `throw` برای کنترل جریان عادی برنامه (مانند حلقه‌ها یا شرط‌های معمولی). `throw` فقط برای شرایط **استثنایی** است.
- پرتاب کردن داده‌هایی که شیء `Error` نیستند.

## نکات مهم
- بعد از دستور `throw`، هیچ کدی در همان بلوک اجرایی اجرا نمی‌شود.
- خطای پرتاب‌شده باید در جایی از Call Stack مدیریت شود، در غیر این صورت باعث توقف کامل برنامه می‌شود.
- پیام خطا باید واضح، توصیفی و به زبان انگلیسی (برای سازگاری با ابزارها) باشد.

## تمرین
1. تابعی بنویسید به نام `withdraw(balance, amount)`. اگر `amount` بیشتر از `balance` بود، یک `Error` با پیام "Insufficient funds" پرتاب کند. در غیر این صورت، `balance` جدید را `return` کند.
2. کد زیر را اجرا کنید و توضیح دهید چرا خط `"This will not run"` هرگز چاپ نمی‌شود:
   ```js
   try {
       console.log("Start");
       throw new Error("Stop!");
       console.log("This will not run");
   } catch (e) {
       console.log("Caught");
   }
   ```

## جمع‌بندی
دستور `throw` ابزار اصلی ما برای اعلام شرایط غیرعادی در کد است. با پرتاب کردن اشیای `Error` استاندارد، ما به سیستم و توسعه‌دهندگان دیگر این امکان را می‌دهیم که خطا را به‌درستی ردیابی و مدیریت کنند.
```

# فایل `05-try-catch.md`

```markdown
# فصل ۵: ساختار try...catch

## مقدمه
حالا که یاد گرفتیم چگونه خطا پرتاب می‌شود، باید یاد بگیریم چگونه آن را "بگیریم" و مدیریت کنیم تا برنامه متوقف نشود. ساختار `try...catch` مکانیزم اصلی جاوااسکریپت برای این کار است.

## مفهوم اصلی
### ۵.۱ ساختار try...catch
این ساختار از دو بلوک اصلی تشکیل شده است:
```js
try {
  // کدی که احتمال می‌دهیم باعث پرتاب خطا شود
} catch (error) {
  // کدی که در صورت وقوع خطا اجرا می‌شود
}
```

### ۵.۲ مثال ساده
```js
try {
  const result = JSON.parse("invalid json string");
  console.log(result);
} catch (error) {
  console.error("An error occurred:", error.message);
}
```
**خروجی:** `An error occurred: Unexpected token i in JSON at position 0`
**دلیل:** تابع `JSON.parse` نمی‌تواند رشته نامعتبر را تجزیه کند و یک `SyntaxError` پرتاب می‌کند. اجرای بلوک `try` بلافاصله متوقف شده و کنترل به بلوک `catch` منتقل می‌شود.

### ۵.۳ نحوه اجرای try و catch
- اگر در بلوک `try` **هیچ خطایی رخ ندهد**، بلوک `catch` کاملاً نادیده گرفته می‌شود.
- اگر خطایی رخ دهد، اجرای خطوط بعدی از نقطه خطا در بلوک `try` **متوقف می‌شود** و کنترل فوراً به بلوک `catch` منتقل می‌گردد.

### ۵.۴ متغیر error در catch
متغیر `error` (که می‌توانید نام آن را هر چیزی بگذارید، مثلاً `err` یا `e`) حاوی شیء خطای پرتاب‌شده است.

```js
try {
  throw new Error("Test error");
} catch (error) {
  console.log(error.name);    // خروجی: "Error"
  console.log(error.message); // خروجی: "Test error"
}
```

### ۵.۵ Optional Catch Binding (اتصال اختیاری catch)
در ECMAScript 2019، اگر به خود شیء خطا نیازی نداشته باشید، می‌توانید نام متغیر را حذف کنید. این کار برای زمانی مفید است که فقط می‌خواهید بدانید عملیات شکست خورده است، بدون اینکه به جزئیات خطا اهمیت دهید.

```js
try {
  riskyOperation();
} catch {
  console.log("Operation failed, using default value.");
}
```

### ۵.۶ محدوده متغیر catch (Scope)
متغیر `error` فقط در داخل بلوک `catch` در دسترس است (Block-scoped). تلاش برای دسترسی به آن در خارج از بلوک باعث `ReferenceError` می‌شود.

```js
try {
  throw new Error("Test");
} catch (error) {
  console.log(error.message); // معتبر
}
// console.log(error); // مثال اشتباه: ReferenceError: error is not defined
```

### ۵.۷ مدیریت خطا در توابع
گاهی اوقات مدیریت خطا درون خود تابع منطقی‌تر است تا به فراخواننده تحمیل شود.

```js
function getUserName(user) {
  try {
    return user.name;
  } catch (error) {
    return "Unknown user";
  }
}
```
**مزایا:** تابع همیشه یک مقدار معتبر برمی‌گرداند و فراخواننده نیازی به نوشتن `try...catch` ندارد.
**معایب:** اگر خطا ناشی از یک باگ برنامه‌نویسی باشد (مثلاً `user` باید همیشه تعریف شده باشد)، این کد آن باگ را پنهان می‌کند و عیب‌یابی را سخت می‌سازد.

## اشتباهات رایج
- قرار دادن کدهای زیاد و نامرتبط در یک بلوک `try` بزرگ (که تشخیص محل دقیق خطا را سخت می‌کند).
- استفاده از `try...catch` برای کنترل جریان عادی برنامه (مثل جایگزینی برای `if/else`).

## نکات مهم
- `try...catch` فقط خطاهای **زمان اجرا (Runtime)** را مدیریت می‌کند و روی خطاهای سینتکس (Syntax Errors) که در مرحله تجزیه رخ می‌دهند، تأثیری ندارد.
- همیشه سعی کنید بلوک `try` را تا حد امکان کوچک و متمرکز نگه دارید.

## تمرین
1. تابعی بنویسید که یک آرایه و یک ایندکس دریافت کند. اگر ایندکس خارج از محدوده بود، در بلوک `catch` مقدار `null` برگرداند، در غیر این صورت مقدار آن ایندکس را برگرداند.
2. چرا کد زیر خطای `ReferenceError` را مدیریت نمی‌کند و برنامه کرش می‌شود؟
   ```js
   try {
       console.log(nonExistentVariable);
   } catch (e) {
       console.log("Caught");
   }
   // راهنمایی: به زمان تجزیه (Parse-time) در مقابل زمان اجرا فکر کنید. (نکته: در واقع این کد کار می‌کند و ReferenceError یک خطای زمان اجرا است! اما اگر nonExistentVariable در مرحله Parse به عنوان متغیر نامعتبر شناسایی نمی‌شد چه؟ در JS مدرن، ReferenceError توسط try...catch قابل گرفتن است. سؤال را این‌گونه اصلاح کنید: چرا try...catch نمی‌تواند خطای سینتکس را بگیرد؟)
   ```
   *تصحیح تمرین ۲:* توضیح دهید چرا `try...catch` نمی‌تواند خطای زیر را بگیرد:
   ```js
   try {
       eval("invalid syntax !!!");
   } catch (e) {
       // آیا این اجرا می‌شود؟ بله، چون eval در زمان اجرا تجزیه می‌شود.
       // اما کد زیر چطور؟
       // { invalid syntax } // خارج از eval، در خود کد اصلی
   }
   ```

## جمع‌بندی
ساختار `try...catch` ابزار قدرتمندی برای مدیریت خطاهای زمان اجرا است. با استفاده صحیح از آن، می‌توانیم از توقف برنامه جلوگیری کنیم و در صورت بروز مشکل، واکنش مناسبی نشان دهیم. در فصل بعد، با بخش تکمیلی این ساختار، یعنی `finally` آشنا خواهیم شد.
```
